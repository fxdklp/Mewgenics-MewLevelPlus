# Mewgenics「10 级后继续升级法术/被动」Mod 可行性调研报告

> 调研日期：2026-10-31
> 调研方式：直接读取本地游戏数据文件（E:\SteamLibrary\steamapps\common\Mewgenics\data）+ N 网/GitHub 开源资料

---

## 一、核心结论（TL;DR）

1. **你的 mod 核心功能无法用数据文件实现。** 升级选项的抽取算法（几级出法术/被动/属性、何时升级、10 级后出什么）**硬编码在 C++ 代码 `LevelUpScreen.cpp` 里**，数据文件（`.gon/.csv` + `.merge/.append/.patch`）只提供「池子」和「参数」，改不了算法本身。
2. **必须走代码层（DLL hook），可行。** N 网已有一整套代码级框架，能直接 hook 游戏函数。有两条路：
   - **路径 A（推荐，简单）**：Mewgenics Mod Framework（C# SDK，.NET 9 编译）
   - **路径 B（底层，灵活）**：Mewjector（C/C++，RVA 级函数 hook）
3. **数据文件能做的只是外围配合**：改能力/被动池、改属性升级池、改重 roll 次数等。

## 二、游戏数据结构（我实际读到的真实文件）

游戏根目录有一个已解包的 `data\` 文件夹（部分完整 `.gon` + 部分 `.merge/.patch` 补丁），
让我不用解包 4.8GB 的 `resources.gpak` 就直接看到了真实结构。

### 2.1 `data\classes\classes.gon` — 职业定义（关键）

每个职业（Fighter/Hunter/Mage/Medic/Tank/Thief/Colorless）包含：

| 字段 | 含义 | 与你 mod 的关系 |
|---|---|---|
| `ability_pool [ ... ]` | 该职业可学的法术池（约 50 个） | 「随机法术」从这里抽 |
| `passive_pool [ ... ]` | 该职业可学的被动池（约 25 个） | 「随机被动」从这里抽 |
| `starter_abilities [ ... ]` | 开局随机给的初始法术池 | 无 |
| `levelup_stats [str con spd]` | 升级时「属性提升」可选的属性 | 「属性提升」选项从这里出 |
| `innate_passives { AddLevelUpRerolls 14 }` | 升级时重 roll 次数 | 可调 |
| `attack_pool [ ... ]` | 普通攻击 | 无 |
| `tutorial_levelup_active_pool [...]` | 教学关升级池（仅 Colorless） | 无 |

### 2.2 升级版（+ 版）的命名规则

**数据里是 `Name` → `Name2`，不是 `Name+`。** 例如 `mage_abilities.gon.merge` 里：

```
ForbiddenFlame   { ... }
ForbiddenFlame2  { ... }   ← 这就是「+ 升级版」
```

### 2.3 `data\passives\disorders.gon` — 疾病结构

疾病（disorder）本质是 `class Disorder`，含 `name/desc/passives/stats/lock_item_slot`，
即「被动 + 专属槽位」。与你说的「2 个疾病槽位」对应。

## 四、N 网 mod 技术栈（现状，2026-10）

| 层 | 工具 | 能做什么 | 你的 mod 用不用 |
|---|---|---|---|
| 数据层 | `.merge/.append/.patch` 打补丁 | 改数值/文本/池子 | 外围配合 |
| 资源层 | Mewtator（mods/1） | 解包 gpak、管理 mod | 部署/测试用 |
| 代码层 | Mewjector（mods/218，开源） | DLL 注入 + RVA 函数 hook | **核心（可选）** |
| 代码层 | Mewgenics Mod Framework（mods/183） | C# SDK，读写能力/被动/职业目录 | **核心（推荐）** |

### Mewjector（GitHub: githubuser508/mewjector，MIT 开源）

- 伪装成 `version.dll` 注入，转发系统调用 + 加载 mod DLL。
- **Mod API v3** 提供 `MJ_InstallHook`（可链式函数 hook）、`MJ_GetGameBase`（游戏基址）、`MJ_QueryHook`（RVA 处 hook 数）等——**可以按 RVA 直接 hook `LevelUpScreen` 里的函数**。
- 与 Mewtator 通过 `chainloader.ini` 自动联动。

### Mewgenics Mod Framework（mods/183，C# SDK）

- 一个 mod = 一个简短 C# 类，继承 `MewgenicsMod`，`OnLoad()` 里注册逻辑。
- 提供：**所有物品/能力/被动/职业/敌人的目录**（读、加、复制编辑）、游戏事件、
  「用 C# 代码实现自定义被动和状态的行为」、战斗动作、「对其它一切打补丁和 hook」。
- 需要 **.NET SDK 9** 编译；加载器 `version.dll` 在 GitHub。

### 参考开源项目

- `polymeric/mewgenics_randomize_item_picks` — 已逆向游戏结构 + 签名扫描的 C++ 基础框架，可作为 C++ hook 的参考。

## 五、你的需求 → 技术映射

| 你的需求 | 实现方式 |
|---|---|
| 10 级后继续升级法术/被动 | **代码 hook LevelUpScreen**（数据层做不到） |
| 交替刷新（法术/被动） | **代码内维护「下次刷哪种」标志** |
| 优先刷已有未满级 → 满级后刷替换 | **代码逻辑**（需读猫当前能力 + 判断是否满级） |
| 本次升级后续只出属性 | **代码逻辑** |
| 槽位上限 1/4/2/2 不变 | 保持默认（原版即 4 法术 2 被动 2 疾病） |
| 「随机法术/被动」的池子来源 | 数据层的 `ability_pool`/`passive_pool` |
| 满级判定（Name vs Name2） | 代码里判断是否已持有 `Name2` |

## 六、实现路径（两条）

### 路径 A：Mewgenics Mod Framework（C#，推荐）

- 优点：写 C# 简单、有现成目录 API、有 F10 菜单、改起来快。
- 待确认：SDK 是否**直接暴露「升级选项生成」的 hook**（文档列了「新一天/战斗/伤害/死亡/购买/状态」等事件，**未单列升级**，但声明「对其它一切打补丁和 hook」，需拿到 SDK 后实测）。

### 路径 B：Mewjector（C/C++，兜底）

- 优点：最底层，RVA 级 hook，一定能 hook 到 `LevelUpScreen` 的函数。
- 缺点：要反编译 `Mewgenics.exe` 定位函数地址、要写 C++、维护成本高。

> **建议：先试路径 A，实测 SDK 是否有升级 hook；没有就降级到路径 B。**

## 八、风险与待确认

1. **版本匹配**：本机游戏 Steam buildid = `25143593`（exe 更新于 2026-10-04）；
   SDK 适配内部版本 `1.1.21239`。SDK 自带 `GameAddressMap` 会在加载时校验构建版本，
   若偏移不匹配会自行报错，需届时核对。
2. **编译工具链**：NativeAOT 需要 MSVC C++ 构建工具（`link.exe`），已装 .NET 9 SDK，
   正在补装 VS2022 Build Tools 的 C++ 工作负载。
3. **反作弊/成就**：第三方 DLL 注入可能影响 Steam 成就（多数社区 mod 如此，介意需注意）。
4. **游戏更新会失效**：每次游戏大更新，代码 hook 的地址可能要重定位（SDK 自带地址会自校验）。
